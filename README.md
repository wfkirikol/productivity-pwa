# Ритм: задачи и финансы

PWA для активностей, связанных финансовых операций и личных заметок по психологии и конфликтологии.

## Возможности

- Активности со статусом, прогрессом, сроком и периодичностью.
- Доходы и расходы с необязательной привязкой к активности.
- При удалении активности финансовая операция сохраняется, а ссылка на задачу обнуляется.
- Приоритет, оценка длительности и требуемый уровень энергии для задач.
- Чек-листы подзадач, сохраняемые вместе с активностью.
- Фокус-сессии с восстановлением активного таймера после перезагрузки и учётом затраченного времени.
- Автоматическое создание следующего экземпляра повторяющейся задачи после завершения.
- План дня с лимитом времени, ранжированием задач и горизонтом на ближайшие 7 дней.
- Заметки в разделах «Мысли», «Психология» и «Конфликтология».
- ИИ-поддержка: мотивация для старта, совет по времени и декомпозиция задачи в чек-лист.
- Светлая, тёмная и лесная темы; установка PWA и кэширование оболочки приложения.
- Обновление данных после мутаций через TanStack Query.

## Расширенные функции задач

Функции расположены от меньшей сложности реализации к большей:

| Функция | Польза | Изменения в БД | Сложность |
| --- | --- | --- | --- |
| Приоритет, оценка времени и уровень энергии | Быстрее выбрать подходящую задачу под свободное время и текущее состояние. | В `activities`: `priority`, `estimated_minutes`, `energy_level`. | Легко |
| Чек-листы подзадач | Превратить крупное дело в небольшие отмечаемые шаги. | Таблица `activity_checklist_items`: `activity_id`, `title`, `completed`, `position`. | Средне |
| Фокус-сессии | Видеть фактическое время работы и возвращаться к запущенному таймеру после перезагрузки. | Таблица `focus_sessions`; накопленное время `focus_seconds` в `activities`. | Средне |
| Автоповтор задач | После выполнения повторяющейся задачи следующая появляется автоматически; повторное завершение не создаёт дубликат. | В `activities`: `parent_activity_id`, `next_occurrence_id`. | Сложно |
| Планировщик с лимитом времени | Разложить открытые задачи по доступному времени, приоритету и сроку на горизонте семи дней. | Таблица `daily_plans`: `user_id`, `plan_date`, `available_minutes`. | Сложно |

## ИИ-модуль

`core/config.py` загружает настройки из `.env`; `core/logger.py` настраивает общий вывод в консоль и `logs/productivity.log`. `adapters/openrouter` изолирует асинхронный HTTP-вызов, а `adapters/prompts` хранит сценарии мотивации, тайм-менеджмента и декомпозиции.

Для реальных ответов создайте `.env` на основе `.env.example` и задайте `OPENROUTER_API_KEY`. Используется только модель `google/gemma-4-31b-it:free`; таймаут — 30 секунд. Без ключа приложение продолжит работать и вернёт безопасную офлайн-подсказку; ответы `429`, сетевые ошибки и таймауты также переходят на fallback.

AI API: `POST /api/v1/ai/activities/{id}/motivation`, `POST /api/v1/ai/time-management`, `POST /api/v1/ai/decompose`.

## Запуск backend

Из корня проекта в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload
```

API: `http://127.0.0.1:8000/api/v1`; интерактивная документация: `http://127.0.0.1:8000/docs`.

По умолчанию SQLite сохраняет данные в `productivity.db`. Для другой БД задайте переменную окружения `DATABASE_URL` до запуска backend.

## Запуск frontend

Нужен Node.js 20 или новее:

```powershell
cd frontend
npm install
npm run dev
```

Vite открывает приложение на `http://localhost:5173` и проксирует `/api` на backend.

## Изоляция пользователей

В этой версии API ограничивает записи значением заголовка `X-User-Id`; при его отсутствии используется пользователь `1`, чтобы локальный прототип запускался без настройки входа. Это только механизм разработки, не аутентификация: перед публикацией в интернете необходимо заменить его на проверенную сессию или токен и получать `user_id` из аутентифицированного пользователя. API намеренно отвечает `404`, если запись отсутствует или принадлежит другому `X-User-Id`.
